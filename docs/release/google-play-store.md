### Network endpoints the release client calls (all HTTPS or WSS)

- `GET /v1/game-version`: version check (`EchoUpdates`, `EchoClient.fetchGameVersion`)
- `POST /v1/auth/device`: creates or refreshes the player account with `device_id` (random UUID from `EchoPlayerSession.deviceId()`) and the chosen `username`
- `GET /v1/auth/me`, `PATCH /v1/auth/username`
- `PUT /v1/auth/credentials`: optional email and password linking (`EchoPlayerAuthGate` email field, `EchoClient.setCredentials`)
- `POST /v1/echoes`: Hero Echo upload (echo id, depth, game version, hero class, level, HP, game seed, timestamp, base64 gameplay snapshot of equipment and talents, source client, easy mode, policy input)
- `GET /v1/echoes/{depth}`, `POST /v1/echoes/policy`: fetches ranked echoes and sends a solo echo's loadout to get a fight policy
- `POST /v1/leaderboard/results`, `GET /v1/leaderboard/{depth}`: fight results (boss won, depth, damage dealt and taken, turns, player class, timestamp)
- `POST /v1/integrity/report`: anti-cheat report (reason, hero class and level, depth, seed, save slot, `client_id` = device id)
- World socket (`wss://` on the backend origin, served by hero-echoes `src/app/v1/world/socket`): village presence (hero class, cell, facing), **free-text chat**, chat reports, mute state. Identity = device id + username (`worldnet/WorldNet.java identity()`). Village always joins. During runs, chat only connects if the player turns on the world chat setting
- Sentry ingest: crashes, errors, traces, logs, and player-filed error reports (tagged with the username)

## 9. API automation notes (DRAFTED)

**Google Play Developer API (androidpublisher v3)** can do, inside an `edits` transaction and then `edits.commit`:

- `edits.details`: default language, contact email, phone, and website. **Not** category, tags, or app name at creation
- `edits.listings`: title, short description, full description, and video URL per language
- `edits.images`: `icon`, `featureGraphic`, `phoneScreenshots`, `sevenInchScreenshots`, `tenInchScreenshots`, `tvBanner`, `wearScreenshots`, etc. (upload, list, delete)
- `edits.bundles.upload` plus `edits.tracks.update`: AAB upload and releases to internal, closed (alpha or custom), open, and production tracks, with release notes, staged rollout, and `changesNotSentForReview`
- `edits.testers`: Google Groups for closed tracks. Individual tester emails are managed in the Console
- `applications.dataSafety`: POST the Data safety **CSV** (export the template from Console > Data safety first)
- `monetization.onetimeproducts` / `inappproducts`: not used at launch (**resolved 2026-10-08:** no IAP; was going to be `support_500`)
- Also reviews (reply), purchases and voided purchases, and `edits.expansionfiles` (not needed)
- Tooling options: Gradle Play Publisher (`com.github.triplet.play`) or fastlane `supply`. Either can push the listing text and images from a folder such as `docs/release/play/`

**Console UI only:**

- Creating the app (name, default language, app/game, free/paid, declarations)
- **First AAB upload.** The API can't create a package, so the first bundle is usually uploaded by hand
- Content rating (IARC questionnaire), target audience and content, ads, app access, advertising ID, government/financial/health/news declarations, privacy policy URL, and the data deletion questions (or use the CSV for Data safety)
- Store settings: category, tags, contact details (also possible via API), external marketing, Play Games on PC
- Countries and pricing setup, the payments profile, closed-test tester lists, the production access application, managed publishing, and pre-registration
- Inviting the service account (Users and permissions)

**Steps for Marwan to create a service account JSON key** (Google no longer requires linking a Cloud project in Play Console; source: https://developers.google.com/android-publisher/getting_started):

1. Google Cloud Console: create or select a project (e.g. `iatdb-play-publisher`).
2. APIs & Services > Library: enable **Google Play Android Developer API**.
3. IAM & Admin > Service Accounts > **Create service account** (e.g. `play-publisher`). No Cloud IAM roles are needed.
4. Open the service account > **Keys** > Add key > Create new key > **JSON**. Store the file outside the repo (e.g. `%USERPROFILE%\.secrets\iatdb-play-publisher.json`). Never commit it, paste it into chat, or put it in `.env` without a gitignore check.
5. Play Console > **Users and permissions** > Invite new users. Enter the service account email (`play-publisher@<project>.iam.gserviceaccount.com`).
6. App permissions: add **I am the Dungeon Boss** only (not account-wide). Grant _View app information (read-only)_, _Manage store presence_, _Release to testing tracks_, _Manage testing tracks and edit tester lists_, and, only when ready, _Release to production, exclude devices, and use Play App Signing_. For product creation, grant the in-app products permission the Console offers (it's under financial/monetization). Don't grant Admin.
7. Click **Invite user**. Permissions can take up to a day to start working. Test with a read-only call (e.g. `edits.insert` then `edits.details.get`, followed by `edits.delete`) before any write.
